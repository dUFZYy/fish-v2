    46	// ===================== Leistungsstufen (#107) =====================
    47	//
    48	// Der Umzug hat drei Posten je Bild dazugebaut, und ALLE DREI haengen an der
    49	// Pixelzahl der Effekt-Ebene: die Szene wird gerastert, dann in voller Groesse
    50	// zur GPU kopiert, dann laeuft der Shader pixelweise darueber. Bei 1170x2532
    51	// sind das knapp drei Millionen Pixel, dreimal angefasst.
    52	//
    53	// Deshalb ist die Aufloesung der Effekt-Ebene der Regler, nicht ein Effekt.
    54	// Wasser, Licht und Truebung sind niederfrequent; halbiert man die Kante,
    55	// fallen alle drei Posten auf ein Viertel. Es geht nur, weil die OBERFLAECHE
    56	// (Schrift, Menues, Holz, HUD) eine eigene Canvas-2D-Ebene DARUEBER ist und
    57	// in voller Schaerfe bleibt - genau der Hybrid aus SPIKE-PHASER.md.
    58	//
    59	//   skala    Faktor auf die Aufloesung der Effekt-Ebene (Szene-Puffer UND
    60	//            Phaser-Flaeche, immer gemeinsam - unterschiedliche Groessen
    61	//            heissen entweder Matsch oder Flimmern)
    62	//   ringe    Bloom: 2 Ringe = 12 Abtastungen, 1 Ring = 6, 0 = aus
    63	//   oktaven  Kaustik: 2 = grobes Netz + feines Flirren, 1 = nur das grobe
    64	//            (dazu: keine Lichtschaechte, im Tiefsee-Zweig ein Rauschen
    65	//            statt fBm und eine Schneeebene statt zweien)
    66	//   takt     Wie oft die Welt-Ebene ueberhaupt neu gebaut wird: 1 = jedes Bild,
    67	//            2 = jedes zweite. Das halbiert Kopie, Upload UND Shader auf einen
    68	//            Schlag - und zwar ohne ein einziges Pixel aufzugeben. Bezahlt wird
    69	//            mit der Bewegung: das Wasser und die Fische laufen dann mit 30
    70	//            Bildern, waehrend Menue und HUD bei 60 bleiben. Deshalb erst auf
    71	//            der Notstufe.
    72	//   uiDpr    Deckel fuer die OBERFLAECHE. Bleibt bis zur letzten Stufe bei 3 -
    73	//            dort haengt die Schrift dran, das gibt man als Letztes auf.
    74	//
    75	// STUFE 0 STEHT SEIT RUNDE 3 BEI uiDpr 3, nicht mehr bei 2 (#107). Runde 1 hat
    76	// sie als Notstufe gebaut, und eine Notstufe darf Schaerfe opfern. Inzwischen
    77	// ist sie auf einem Telefon die VOREINSTELLUNG - und dann muss sie genau das
    78	// sein, was das Spiel vor dem Umzug war: eine einzige, undurchsichtige
    79	// Canvas-2D-Ebene in voller Aufloesung. Das ist der Stand, den Dustin monatelang
    80	// gespielt hat. Wer es trotzdem billiger braucht: Diagnose -> UI-DPR.

   278	  //   1. Aufloesung kostet beim RASTERN fast nichts. Neun Mal weniger Pixel

   284	  //

   287	  // Sie wegzunehmen ist deshalb keine Sparmassnahme, sondern das Streichen
   288	  // einer Rechnung ohne Gegenleistung.

   291	  // die Welt-Ebene liegt UNTER einem Brechungs-Shader. Was er zeigt, ist

   293	  // Schrift, Menues, Holz, HUD — liegt darueber und bleibt unangetastet bei
   294	  // vollen 3x. Genau dafuer gibt es den Hybrid.
   295	  //
   296	  //   Deckel   Aufloesung   Upload je Bild   davon
   297	  //   3x       1170x2532    11,85 MB         100 %

   299	  //   1.5x      585x1266     2,96 MB          25 %
   300	  //
   301	  // 2x ist die Voreinstellung auf Telefonen. Zum Gegenmessen am Geraet:
   302	  // ?weltdpr=3 (der alte Zustand) oder Diagnose -> Welt-DPR.
   303	  // GEMESSEN AUF DEM GERAET, nicht geschaetzt (#107, Runde 5). iPhone 15 Pro
   304	  // Max, Safari, gewachsener Spielstand, nach dem Dunst-Fix in sprites.js:
   305	  //
   306	  //   Welt-Deckel   fps    p95    Hakler/s
   307	  //   1x            58,8    18     0
   308	  //   1,5x          58,8    18     0        <-- das hier
   309	  //   2x            55,6    23     0,33
   310	  //   3x            45,5    24     0
   311	  //   Obergrenze    58,8    17     0        (Leerlauf, nichts gezeichnet)
   312	  //
   313	  // 1,5x ist die HOECHSTE Stufe, die volle 60 Bilder haelt, und sie haelt sie
   314	  // ohne einen einzigen Hakler - der p95 liegt eine Millisekunde ueber dem
   315	  // Leerlauf. Darunter (1x) wird es nicht schneller, nur unschaerfer: die
   316	  // Schaumlinie an der Wasserkante wird treppig und Berge und Schilf werden
   317	  // weich (Bildvergleich, 31.08.).
   318	  //
   319	  // Warum nicht 2x oder 3x: was dort noch fehlt, ist kein Effekt und keine

   353	  // Basis-Aufloesung der Welt-Ebene, bevor die Stufe daran dreht.
   354	  baseDpr() {
   355	    const geraet = window.devicePixelRatio || 1;
   356	    const deckel = istTelefon() ? this.WELT_DECKEL_TELEFON : 2;
   357	    return this._dprFest || Math.min(geraet, deckel);
   358	  },
   359	  // Tatsaechliche Aufloesung der Effekt-Ebene. Unter 1x wird es matschig statt
   360	  // schnell, deshalb der Boden.
   361	  //
   362	  // ===================== Der Deckel faellt (#107, der Umbau) ===============
   363	  //
   364	  // `WELT_DECKEL_TELEFON` war der Preis fuer den Upload: die Welt-Ebene lief
   365	  // auf 1,5x, weil jedes Bild ihre gesamte Pixelzahl ueber den Bus musste, und
   366	  // das ist der EINZIGE Posten, der quadratisch mit der Aufloesung waechst.
   367	  // Bezahlt hat ihn die Schaerfe der Fische - Dustin hat es sofort gesehen
   368	  // ("die See-Fische sind im Verhaeltnis zum Aquarium unscharf"), und im Bild
   369	  // standen zwei Aufloesungen nebeneinander.
   370	  //
   371	  // Im GPU-Weg gibt es diesen Posten nicht mehr. Also gibt es auch den Deckel
   372	  // nicht mehr: die Welt laeuft in DERSELBEN Aufloesung wie die Oberflaeche.
   373	  // Damit ist die zweite Aufloesung aus dem Bild verschwunden, und der
   374	  // See-Fisch ist so scharf wie der Becken-Fisch.
   375	  //
   376	  // ===================== Was 3x TROTZDEM noch kostet ======================
   377	  //
   378	  // Der Upload ist weg, das Rastern ist weg - aber eine bildschirmfuellende
   379	  // WebGL-Ebene wird vom BROWSER noch mit der Oberflaeche zusammengesetzt, und
   380	  // das kostet Flaeche. Gemessen auf dem Entwicklungsrechner (390x844@3x,
   381	  // CPU 6x gedrosselt) ist der Unterschied zwischen 1,5x und 3x groesser als
   382	  // alles, was der Umbau innerhalb von JavaScript spart. Deshalb bleibt die
   383	  // Aufloesung ein REGLER und keine Entscheidung:
   384	  //
   385	  //   ?weltdpr=1.5   die Aufloesung von vorher (Fische wieder weicher)
   386	  //   ?weltdpr=3     Voreinstellung: eine Aufloesung im ganzen Bild
   387	  //
   388	  // Welcher Wert auf DUSTINS Geraet richtig ist, sagt der Prueflauf dort
   389	  // (?wache=1), nicht dieser Rechner.
   390	  // MESSUNG VOM 01.09., Safari auf dem iPhone 15 Pro Max, 430x775 @3x:
   391	  // beide Wege liefern bei DERSELBEN Aufloesung dieselbe Bildrate (See 66,7 /
   392	  // Riff 66,7 / Tiefsee 47,6, null Hakler). Der Deckel von 1,5x war der Preis
   393	  // fuer den Upload — und dieser Preis ist mit dem Backblech gefallen, nicht
   394	  // mit dem GPU-Umbau. Deshalb gilt die volle Aufloesung jetzt auf BEIDEN
   395	  // Wegen: die zwei Aufloesungen im Bild (matschige See-Fische gegen scharfe
   396	  // Becken-Fische) waren Dustins erster und haerteste Kritikpunkt.
   397	  // Zum Gegenmessen: ?weltdpr=1.5
   398	  weltDpr() {
   399	    return this._dprFest || this.uiDpr();
   400	  },
   401	  // Deckel fuer die Oberflaeche (script.js: resizeCanvas).
   402	  //
   403	  // `uiFest` ist ein MESSGERAET, kein Regler (Runde 3, #107). Es gibt eine
   404	  // Frage, die niemand beantwortet hat: im Hybrid liegen ZWEI bildschirm-
   405	  // fuellende Ebenen uebereinander - die WebGL-Ebene und darueber `#gameCanvas`
   406	  // mit Alpha, das jedes Bild geleert, neu bemalt und vom Compositor
   407	  // darueber gemischt wird. Mit ?welt=c2d gibt es nur EINE, undurchsichtige.

   409	  // Projekts fasst ihn an. `?weltui=2` halbiert die Flaeche der oberen Ebene
   410	  // (bei 1170x2532: 2,96 -> 1,32 Millionen Pixel) und kostet Schriftschaerfe.
   411	  // Wird es damit spuerbar besser, ist der Compositor die Spur.
   412	  // ===================== Textur und Ausgabe getrennt (#107, Runde 11) =====
   413	  //
   414	  // Bis hier hing an EINER Zahl (weltDpr) zweierlei: die Groesse der
   415	  // Szene-Leinwand, die jedes Bild als Textur hochgeht, UND die Groesse der
   416	  // WebGL-Leinwand, in die der Shader sein Ergebnis schreibt. Beide gleich
   417	  // gross - das war nie eine Entscheidung, nur die einfachste Verdrahtung.
   418	  //
   419	  // Dustins Geraetebefund vom 02.09. (Bildzeit-Anzeige beim SPIELEN, nicht
   420	  // im Pruefstand): Welt-DPR 1 gibt stabile 60 fps, alles darueber bricht ein.
   421	  // Der Upload haengt an der Texturgroesse (1x 7 ms, 3x 14 ms) - aber mit
   422	  // Welt-DPR 1 wird eben auch der SHADER nur in 430x775 gerechnet und das
   423	  // Ergebnis vom Compositor dreifach hochgezogen. Dann sind nicht nur die
   424	  // Fische weich, sondern auch Wellenlinie, Kaustik und Glitzern - genau die
   425	  // Effekte, die ohne Upload gratis in voller Schaerfe zu haben waeren.
   426	  //

   428	  // `szene()`: p / uRes), also darf die Textur eine andere Groesse haben als
   429	  // die Ausgabe. `ausDpr` ist die Ausgabe. Ohne `?weltaus=` verhaelt sich
   430	  // alles wie vorher (Ausgabe = Textur).
   431	  //
   432	  //   ?weltdpr=1&weltaus=3   Textur 1x (billiger Upload), Shader in 3x
   433	  //   ?weltdpr=1&weltaus=2   Mittelweg, wenn 3x im Compositing zu teuer ist
   434	  //
   435	  // Was das NICHT loest: die Fische liegen in der Textur und bleiben bei 1x
   436	  // weich. Dafuer ist der naechste Schritt gedacht (Fische als Sprites in
   437	  // voller Aufloesung ueber der Textur).
   438	  _ausFest: 0,
   439	  ausDpr() { return this._ausFest || this.weltDpr(); },

   441	  uiFest: 0,
   442	  uiDpr() {
   443	    const d = window.devicePixelRatio || 1;
   444	    if (this.uiFest) return Math.min(d, this.uiFest);
   445	    return Math.min(d, window.innerWidth < 700 ? this.stufe.uiDpr : 2);

   448	  // ===================== Der Welt-Takt (#107, Runde 10) ====================
   449	  //
   450	  // Wird die SZENE in diesem Bild neu gerastert? Nicht: laeuft die Ebene.
   451	  // Das ist der Unterschied, um den es in dieser Runde geht.
   452	  //
   453	  // Bis Runde 9 hiess `takt: 2` (Notstufe): die Welt-Ebene setzt jedes zweite
   454	  // Bild komplett aus - kein Rastern, kein Upload, aber eben auch KEIN
   455	  // Shader-Durchlauf. Das Wasser stand dann jedes zweite Bild still, und weil
   456	  // Brechung, Kaustik und Glitzern allein aus `uTime` leben, sah man genau
   457	  // das: ein Stottern im Wasser, nicht nur groebere Fischbewegung. Deshalb
   458	  // war der Takt bisher nur eine Notbremse und nichts, was man freiwillig
   459	  // einschaltet.
   460	  //
   461	  // Der Geraetebefund vom 01.09. macht daraus etwas anderes. Die Zerlegung
   462	  // sagt: Rastern der Canvas-2D-Szene rund 15 ms, Shader 0-3 ms, Compositing
   463	  // 2-4 ms. Der teure Posten ist NUR das Rastern - und See und Riff landen
   464	  // bei voellig verschiedenem Inhalt auf derselben Bildrate (43,5), also
   465	  // zahlen wir dort fast nur diese feste Gebuehr.
   466	  //
   467	  // Also trennen wir die beiden Takte: die Szene wird seltener gerastert,
   468	  // der Shader laeuft WEITER JEDES BILD ueber die zuletzt hochgeladene
   469	  // Textur, mit frischem `uTime`. Wasserverzerrung, Spiegelung und
   470	  // Sonnenglitzern bleiben damit vollstaendig fluessig - gerade die Effekte,
   471	  // die Dustin als "Gold wert" bezeichnet hat. Groeber wird allein die
   472	  // Bewegung der Motive IN der Textur (Fische, Angler, Wellenlinie).
   473	  //
   474	  // Ob man das sieht, entscheidet das Auge auf dem Geraet, nicht diese Datei.
   475	  // `?welttakt=2` und das Duell `?duell=takt` sind dafuer da.
   476	  _tick: 0,
   477	  faellig() {
   478	    if (this.needsFrame) return true;

   480	    // Phaser-Objekte auf der Karte. Ein Takt > 1 wuerde dort keine Arbeit
   481	    // sparen, sondern nur Bewegung schlucken.
   482	    if ((this.gpu || this.dynWeg) && typeof Gpu !== "undefined" && Gpu.bereit) return true;
   483	    const t = this.taktFest || this.stufe.takt || 1;
   484	    if (t <= 1) return true;
   485	    this._tick = (this._tick + 1) % t;
   486	    return this._tick === 0;
   487	  },

   638	  //
   639	  // Das ist kein Uebergehen einer Nutzerentscheidung, sondern das Gegenteil:
   640	  // was in `save.gfx` und `save.gfxDiag` steht, hat niemand als VORLIEBE
   641	  // gewaehlt. Es sind Messgeraete-Stellungen aus zwei Runden Fehlersuche - wer
   642	  // beim Einkreisen einmal VOLL festgenagelt oder den Pfad auf KOPIE gestellt
   643	  // hat, wuerde den neuen Standard sonst nie zu sehen bekommen und haette den
   644	  // Eindruck, es habe sich nichts geaendert. Genau EINMAL, mit Merker; jede
   645	  // Wahl ab jetzt gilt und wird nie wieder angefasst.
   646	  //
   647	  // RUNDE 4 raeumt zusaetzlich `gfxAuto`/`gfxAutoNull` weg, und zwar aus
   648	  // demselben Grund: das ist die Buchfuehrung der Notbremse aus einer Zeit,
   649	  // in der der Hybrid 11,85 MB je Bild hochlud und 40 Prozent der
   650	  // Zeichenbefehle in Fische steckte. Unter diesen Bedingungen ist sie mit
   651	  // Recht nach unten gefahren und hat sich das gemerkt. Die Bedingungen sind

   653	  // `gfxAutoNull >= 3` haette ein Telefon dauerhaft auf Canvas 2D festgenagelt.
   654	  //

  1023	      //   * vierfacher Farbpuffer  (1170x2532: 47 MB statt 11,8)
  1024	      //   * vierfacher Tiefen-/Schablonenpuffer (noch einmal 47 MB)

  1029	      //     viermal so viele davon, und jede kostet Binning und Aufloesung.
  1030	      //

  1032	      // ganzen Shader). Auf einem A17 Pro ist es genau die Art von Kosten, die
  1033	      // sich wie zu wenig Bilder anfuehlt, ohne zu ruckeln.
  1034	      //
  1035	      // Dazu: `stencil` braucht dieser eine Draw-Call nicht. (`depth` setzt
  1036	      // Phaser fest auf true, daran kommen wir nicht heran - ohne MSAA ist es
  1037	      // aber nur noch ein Puffer statt vier.)

  1039	      // Zum Gegenmessen: ?weltmsaa=1 oder Einstellungen -> Diagnose.
  1040	      antialias: true,
  1041	      antialiasGL: this.msaa,
  1042	      stencil: this.msaa,

  1054	    });

  1073	  // ===================== Der Umschalter (#107, der Umbau) ==================
  1074	  //
  1075	  // Es gibt zwei Wege, und beide sind ausgebaut:
  1076	  //
  1077	  //   GPU-OBJEKTE (`modus(true)`)  Die Szene liegt als Phaser-Objekte auf der
  1078	  //     Karte, die Kamera rendert sie, der Wasser-Shader laeuft als
  1079	  //     KAMERA-FILTER darueber. Je Bild geht nichts ueber den Bus. Das ist der
  1080	  //     Weg des Angelplatzes und damit der Weg, in dem das Spiel laeuft.
  1081	  //
  1082	  //   LEINWAND (`modus(false)`)    Die Szene wird in eine Leinwand gerastert,
  1083	  //     die Leinwand geht als Textur hoch, ein Vollbild-Quad zeigt sie. Der
  1084	  //     Weg von vorher. Er bleibt fuer den LADEBILDSCHIRM (intro.js): der malt
  1085	  //     seine eigene Szene mit Schrift und Uebergabe-Fahrt, und ihn
  1086	  //     mitzuziehen haette dem Umbau nichts eingebracht - er laeuft 2,6
  1087	  //     Sekunden und danach nie wieder.
  1088	  //
  1089	  // Umgeschaltet wird selten (einmal beim Verlassen des Ladebildschirms).
  1090	  // Jeder Wechsel legt einen neuen Filter-Controller an - siehe setGpu().
  1091	  modus(gpu) {

  1093	       && typeof Gpu !== "undefined" && Gpu.bereit;

  1095	    return this.gpu;
  1096	  },

  1098	  // Zwischen-Leinwand fuer den KOPIE-Pfad. Auf dem Direkt-Pfad gibt es sie
  1099	  // nicht - dort ist die Szene-Leinwand schon der OffscreenCanvas.
  1100	  _makeBlit() {
  1101	    this.blit = null; this.blitCtx = null;
  1102	    if (this.pfad !== "kopie") return;
  1103	    try {
  1104	      if (typeof OffscreenCanvas !== "undefined") {
  1105	        this.blit = new OffscreenCanvas(this.canvas.width, this.canvas.height);
  1106	        this.blitCtx = this.blit.getContext("2d");
  1107	        // "copy" statt "source-over": der Browser muss den alten Inhalt dann
  1108	        // nicht erst LESEN, um darauf zu mischen. Bei 2,96 Millionen Pixeln je
  1109	        // Bild ist das die halbe Arbeit dieses Postens.
  1110	        this.blitCtx.globalCompositeOperation = "copy";
  1111	      }
  1112	    } catch (e) { this.blit = null; this.blitCtx = null; }

  1115	  // Die Szene auf die GPU bringen. Drei Wege, je nach `pfad` - siehe oben.
  1116	  // Jeder Posten wird EINZELN gemessen, damit auf dem Geraet ablesbar ist,
  1117	  // welcher es ist (perf.js).
  1118	  _upload() {
  1119	    let bmp = null;
  1120	    const t0 = performance.now();
  1121	    if (this.pfad === "sub") {
  1122	      // Der kurze Weg: die Leinwand IST die Quelle. Kein Zwischenbild, keine
  1123	      // Zuteilung, ein Aufruf. `texSubImage2D` nimmt einen Canvas genauso wie
  1124	      // ein ImageBitmap (TexImageSource).
  1125	      //
  1126	      // Und der teuerste: dieser eine Aufruf muss die Leinwand von der GPU
  1127	      // zurueckholen. Was hier gemessen wird, ist deshalb nicht "der Upload",
  1128	      // sondern das Rastern der ganzen Szene plus ein Rueckleseweg.
  1129	      this._glUpload(this.canvas);
  1130	      const dt = performance.now() - t0;
  1131	      Perf.add("upload", dt);
  1132	      this._abProbe(dt);
  1133	      return;
  1134	    }
  1135	    if (this.pfad === "direkt" && this.canvas.transferToImageBitmap) {
  1136	      // Kein Zwischenbild: die Szene liegt schon im OffscreenCanvas.
  1137	      bmp = this.canvas.transferToImageBitmap();
  1138	      Perf.add("bitmap", performance.now() - t0);
  1139	    } else if (this.blitCtx) {
  1140	      this.blitCtx.drawImage(this.canvas, 0, 0);
  1141	      const t1 = performance.now();
  1142	      Perf.add("kopie", t1 - t0);
  1143	      bmp = this.blit.transferToImageBitmap();
  1144	      Perf.add("bitmap", performance.now() - t1);
  1145	    } else {
  1146	      this.tex.refresh();
  1147	      const dt = performance.now() - t0;
  1148	      Perf.add("upload", dt);
  1149	      this._abProbe(dt);
  1150	      return;
  1151	    }
  1152	    const t2 = performance.now();
  1153	    this._glUpload(bmp);
  1154	    bmp.close();
  1155	    Perf.add("upload", performance.now() - t2);
  1156	    // Fuer die A/B-Messung zaehlt der GANZE Weg zur GPU, nicht der letzte
  1157	    // Aufruf: bei `direkt` gehoert das Abtreten des Puffers dazu.
  1158	    this._abProbe(performance.now() - t0);
  1159	  },
  1160	
  1161	  // Der eigentliche Griff an die Textur.
  1162	  //
  1163	  // Phasers `glTexture.update()` ruft IMMER `texImage2D` - das legt die Textur
  1164	  // jedes Bild NEU an. Bei 1170x2532 sind das 11,8 MB Speicher, die je Bild
  1165	  // beschafft und wieder freigegeben werden, obwohl sich nur der Inhalt
  1166	  // aendert. `texSubImage2D` schreibt in dieselbe Textur. Gleiche Bytes ueber
  1167	  // den Bus, aber keine Neuanlage und kein Verwaisen einer Textur, die die GPU
  1168	  // vielleicht noch liest.
  1169	  //
  1170	  // Gebunden wird ueber Phasers eigene Buchhaltung (glTextureUnits/glWrapper),
  1171	  // damit sein Zustandsmodell nicht auseinanderlaeuft.
  1172	  // Klemmen und linear filtern - IMMER ausdruecklich, nie aus dem alten Zustand
  1173	  // der Textur uebernommen. Der Grund ist eine Falle, die uns diese Runde eine
  1174	  // Stunde gekostet hat (#107):
  1175	  //
  1176	  // Die Textur entsteht bei 2x2 Pixeln (der Kniff aus _makeScene), und 2x2 ist
  1177	  // eine ZWEIERPOTENZ. Phaser setzt fuer Zweierpotenzen `REPEAT`. Danach waechst
  1178	  // sie auf 1170x2532 - und das ist KEINE Zweierpotenz mehr. Eine NPOT-Textur
  1179	  // mit REPEAT ist in WebGL 1 unvollstaendig, und eine unvollstaendige Textur
  1180	  // liefert beim Abtasten SCHWARZ. Kein Fehler, keine Warnung, nur ein
  1181	  // schwarzes Bild mit intaktem Wasser darueber.
  1182	  //
  1183	  // Auf dem DOM-Canvas-Weg faellt das nicht auf: dort laeuft der Umbau ueber
  1184	  // `updateCanvasTexture`, und das rechnet den Umlaufmodus aus der NEUEN Groesse
  1185	  // neu aus. Fuer alles andere - und ein OffscreenCanvas ist fuer Phaser
  1186	  // "alles andere" - nimmt `TextureSource.update()` den alten Modus einfach mit.
  1187	  // Deshalb setzen wir ihn hier selbst, in beiden Pfaden gleich.
  1188	  _texParams(gl, w) {
  1189	    return [gl.CLAMP_TO_EDGE, gl.CLAMP_TO_EDGE, gl.LINEAR, gl.LINEAR, w.format];
  1190	  },
  1191	
  1192	  _glUpload(bmp) {
  1193	    const w = this.tex._source.glTexture;
  1194	    const r = this.game.renderer, gl = r.gl;
  1195	    const passt = this._texBereit && w.width === this.canvas.width && w.height === this.canvas.height;
  1196	    if (this.teilupload && passt) {
  1197	      try {
  1198	        r.glTextureUnits.bind(w, 0, true);
  1199	        r.glWrapper.updateTexturing({ texturing: { flipY: w.flipY, premultiplyAlpha: w.pma } });
  1200	        gl.texSubImage2D(gl.TEXTURE_2D, 0, 0, 0, w.format, gl.UNSIGNED_BYTE, bmp);
  1201	        return;
  1202	      } catch (e) {
  1203	        // Irgendein WebView mag das nicht: einmal melden, dann fuer immer der
  1204	        // sichere Weg. Ein Bild kostet das, kein Spiel.
  1205	        console.warn("Teil-Upload nicht moeglich, zurueck auf den vollen Weg:", e);
  1206	        this.teilupload = false;
  1207	      }
  1208	    }
  1209	    w.update(bmp, this.canvas.width, this.canvas.height, false, ...this._texParams(gl, w));
  1210	    this._texBereit = true;
  1211	  },

  1213	  // Weltszene hochladen, Uniforms setzen, EINEN Phaser-Frame zeichnen.
  1214	  // `spielszene` sagt, ob dieses Bild die echte Welt zeigt (script.js) oder den
  1215	  // Ladebildschirm (intro.js). Nur das erste taugt zum Messen - siehe _abProbe.
  1216	  // `neu` (Runde 10): wurde die Szene in diesem Bild frisch gezeichnet?
  1217	  //   true  - rastern und hochladen wie bisher.
  1218	  //   false - die Textur von vorhin bleibt stehen, der Shader laeuft trotzdem
  1219	  //           mit frischem `uTime` darueber. Das ist der ganze Takt-Umbau.
  1220	  // Fehlt das Argument, bleibt es beim alten Verhalten (jedes Bild neu) -
  1221	  // wichtig, weil intro.js und cutscene.js `commit()` ebenfalls rufen.
  1222	  commit(profile, spielszene, neu) {
  1223	    if (!this.active) return;
  1224	    this._p = profile;
  1225	    this._abOk = !!spielszene;
  1226	    if (neu === undefined) neu = true;
  1227	    try {
  1228	      if (this.dynWeg && this.dyn && typeof Gpu !== "undefined" && Gpu.bereit) {
  1229	        // DYN: die Objekte dieses Bildes in die DynamicTexture zeichnen. Das
  1230	        // ist GPU-Arbeit, kein Upload - hier steht nur das Absetzen der
  1231	        // Befehle. Unter "Kopie" verbucht, damit "Upload" ehrlich 0 bleibt.
  1232	        Gpu.rahmenZu();
  1233	        if (neu && !this.messStopp) {
  1234	          const tK = performance.now();
  1235	          this.dyn.clear();
  1236	          this.dyn.draw(Gpu.aktive());
  1237	          if (typeof this.dyn.render === "function") this.dyn.render();
  1238	          Perf.add("kopie", performance.now() - tK);
  1239	        }
  1240	      } else if (this.gpu && typeof Gpu !== "undefined" && Gpu.bereit) {
  1241	        // GPU-Weg: nichts zu rastern, nichts hochzuladen. Nur die Objekte
  1242	        // schliessen, die dieses Bild niemand mehr gebraucht hat.
  1243	        Gpu.rahmenZu();
  1244	      } else if (neu && !this.messStopp) this._upload();   // Pruefstand: siehe script.js
  1245	      const tS = performance.now();
  1246	      // Phasers eigene Schleife anhalten - geht erst hier, nicht in create()
  1247	      // (sonst zeichnet er doppelt; nachgewiesen in tools/sync.js des Spikes).
  1248	      if (this.game.loop.raf && this.game.loop.raf.isRunning) this.game.loop.stop();
  1249	      this.game.loop.step(performance.now());
  1250	      Perf.add("shader", performance.now() - tS);
  1251	      this.frames++;
  1252	      this.needsFrame = false;
  1253	      this._fails = 0;
  1254	    } catch (e) { this._fail(e); }
  1255	  },
  1256	
  1257	  _fail(e) {
  1258	    this._fails++;
  1259	    console.warn("Phaser-Ebene setzt aus (" + this._fails + "):", e);
  1260	    this.suspended = true;
  1261	    if (this._fails >= 3) { this.state = "fehler"; this._hide(); return; }
  1262	    setTimeout(() => { this.suspended = false; this.needsFrame = true; }, 1500);
  1263	  },

  1267	  // zeigt setGpu() beim naechsten Mal auf Objekte einer toten Szene.
  1268	  _gpuVergessen() { this.gpu = false; this.gpuBild = null; this.gpuCtl = null; },
  1269	
  1270	  _hide() {

  1272	    if (this.dyn) { try { this.dyn.destroy(); } catch (e) {} this.dyn = null; }
  1273	    try {
  1274	      if (this.game) {

  1289	  resize() {
  1290	    // resizeCanvas() laeuft bei jedem Ortswechsel: der naechste Frame muss
  1291	    // gezeichnet werden, AUCH wenn die Welt gerade steht (Werbe-Tor beim
  1292	    // Aufbruch) - sonst zeigt die Phaser-Ebene noch den alten Ort.
  1293	    this._rebuild(false);
  1294	  },

  1296	  // Puffer, Textur und Phaser-Flaeche auf die aktuelle Aufloesung bringen.
  1297	  // Ohne `force` passiert nichts, wenn sich nichts geaendert hat: der
  1298	  // Neuaufbau der Textur kostet einen vollen Ruecklese-Frame, und resize()
  1299	  // laeuft bei jedem Ortswechsel.
  1300	  _rebuild(force) {
  1301	    if (this.state !== "bereit" || !this.game) return;
  1302	    this.needsFrame = true;
  1303	    // Stufe 0: die Ebene ist ausgeblendet, ihre Groesse ist bedeutungslos.
  1304	    // Beim Zurueckschalten wird ohnehin neu eingemessen.
  1305	    if (this.tier === 0) return;
  1306	    const d = this.weltDpr();          // Textur: die Szene-Leinwand
  1307	    const a = this.ausDpr();           // Ausgabe: WebGL-Leinwand und Quad
  1308	    const w = Math.max(2, Math.round(window.innerWidth * d));
  1309	    const h = Math.max(2, Math.round(window.innerHeight * d));
  1310	    if (!force && d === this._gameDpr && a === this._ausAlt && w === this.canvas.width && h === this.canvas.height) return;
  1311	    this.dpr = d;
  1312	    this._gameDpr = d;
  1313	    this._ausAlt = a;
  1314	    // GPU-Weg: die Objekte liegen direkt auf der Ausgabe, also in DEREN
  1315	    // Aufloesung - eine Textur gibt es dort nicht.
  1316	    if (typeof Gpu !== "undefined" && Gpu.bereit) Gpu.D = a;
  1317	    if (w !== this.canvas.width || h !== this.canvas.height) {
  1318	      this.canvas.width = w;
  1319	      this.canvas.height = h;
  1320	      this._makeBlit();
  1321	      // Die Textur wird NICHT neu angelegt, nur nachgemessen: `_source.update()`
  1322	      // laeuft ueber `canvasToTexture`, und das liest die Groesse von der
  1323	      // Leinwand selbst und baut die GL-Textur passend um. Ein
  1324	      // `textures.remove()` + `addCanvas()` waere hier ein zweiter
  1325	      // Vollbild-getImageData - siehe boot().
  1326	      const src = this.tex._source;
  1327	      src.width = w;
  1328	      src.height = h;
  1329	      src.flipY = false;
  1330	      this.tex.width = w;
  1331	      this.tex.height = h;
  1332	      // Vor dem Nachmessen die Parameter richtigstellen - siehe _texParams():
  1333	      // `TextureSource.update()` schleppt fuer einen OffscreenCanvas den alten
  1334	      // REPEAT-Modus der 2x2-Textur mit, und NPOT + REPEAT heisst schwarz.
  1335	      const gt = src.glTexture, gl2 = this.game.renderer.gl;
  1336	      if (gt) { gt.wrapS = gt.wrapT = gl2.CLAMP_TO_EDGE; gt.minFilter = gt.magFilter = gl2.LINEAR; }
  1337	      src.update();
  1338	      this.quad.setTextures([this.dynWeg ? "weltdyn" : "weltszene"]);
  1339	      // Nach dem Neuanlegen muss das erste Bild wieder ein voller texImage2D
  1340	      // sein - texSubImage2D schreibt nur in eine Textur, die es schon gibt.
  1341	      this._texBereit = false;
  1342	    }
  1343	    this.game.scale.resize(window.innerWidth * a, window.innerHeight * a);
  1344	    this.game.scale.setZoom(1 / a);
  1345	    this.quad.setSize(window.innerWidth * a, window.innerHeight * a);
  1346	    if (this.dyn) {
  1347	      const dw = Math.max(2, Math.round(window.innerWidth * a)), dh = Math.max(2, Math.round(window.innerHeight * a));
  1348	      if (this.dyn.width !== dw || this.dyn.height !== dh) {
  1349	        try { this.dyn.setSize(dw, dh); } catch (e) { console.warn("DynamicTexture: setSize", e); }
  1350	        this.quad.setTextures(["weltdyn"]);
  1351	      }
  1352	    }
  1353	    // Das Zwischen-Image des Filterwegs haengt an derselben Groesse wie der
  1354	    // Quad. Wird es vergessen, zeigt der Filter nach einem Ortswechsel eine
  1355	    // Szene in der alten Aufloesung - und der Shader rechnet mit der neuen.
  1356	    if (this.gpuBild) this.gpuBild.setDisplaySize(window.innerWidth * a, window.innerHeight * a);
  1357	  },
  1358	
  1359	  // Pfad im laufenden Spiel wechseln. Die Szene-Leinwand ist eine andere
  1360	  // (DOM-Canvas vs. OffscreenCanvas), also muss auch die Textur neu auf sie
  1361	  // zeigen - mit dem 2x2-Kniff aus _makeScene(), sonst kostet das Umhaengen
  1362	  // wieder einen Vollbild-getImageData.
  1363	  setPfad(p) {
  1364	    if (WORLD_PFADE.indexOf(p) < 0 || p === this.pfad) return;
  1365	    this._pfadFest = true;      // eine Wahl von Hand ueberlebt den Neustart
  1366	    this._ab = null;            // und beendet eine laufende Messung
  1367	    this._pfadWechsel(p);
  1368	    this.merkeDiag();
  1369	  },
  1370	
  1371	  // Derselbe Wechsel ohne die Nebenwirkungen von `setPfad`: er merkt sich
  1372	  // nichts und macht den Weg nicht fest. Genau das braucht die A/B-Messung,
  1373	  // die im Lauf zweimal umschaltet und sich erst am Ende festlegt.
  1374	  _pfadWechsel(p) {
  1375	    if (WORLD_PFADE.indexOf(p) < 0 || p === this.pfad) return;
  1376	    this.pfad = p;
  1377	    if (typeof Perf !== "undefined") Perf.stoer(120);
  1378	    if (this.state === "bereit" && this.scene && this.tex) {
  1379	      try {
  1380	        this._makeScene();

  1382	        this.tex = this.scene.textures.addCanvas("weltszene", this.canvas);
  1383	        this.tex._source.flipY = false;
  1384	        // Die Textur ist eine NEUE - das Zwischen-Image des Filterwegs zeigt
  1385	        // sonst weiter auf die alte, die es gleich nicht mehr gibt.
  1386	        if (this.gpuBild) this.gpuBild.setTexture("weltszene");
  1387	        this._texBereit = false;
  1388	        this._gameDpr = -1;              // _rebuild soll wirklich neu einmessen
  1389	        this._rebuild(true);
  1390	      } catch (e) { this._fail(e); }
  1391	    }
  1392	  },

  1416	  // Heute laeuft der Wasser-Shader als EIN Vollbild-Quad, das die Weltszene aus
  1417	  // einer jedes Bild hochgeladenen Leinwand liest. Der Umbau, auf den alles

  1419	  // Kamera rendert sie in einen Framebuffer, und der Wasser-Shader laeuft als

  1422	  // WAS HIER SCHON DRIN IST, UND WAS NOCH NICHT
  1423	  //
  1424	  // Drin ist die HALBE Kette: der Filter. Der Szeneninhalt ist einstweilen noch
  1425	  // ein einziges Phaser-Image, das dieselbe hochgeladene Leinwand zeigt wie
  1426	  // vorher. Dieser Zustand ist deshalb NICHT schneller als der Quad, sondern
  1427	  // langsamer - er hat denselben Upload und einen Vollbild-Durchgang mehr.

  1432	  // Bildschirm. Das ist ein Vollbild-Schreiben und ein Vollbild-Lesen mehr als

  1481	    try {

  1486	      if (!rn._nodeConstructors[this.WELT_FILTER]) {

  1666	// ===================== Parallaxe (#95, gesetzt) =====================
  1667	// Die Kulissen-Ebenen bewegen sich gegeneinander: was weiter weg ist, folgt
  1668	// dem Blick staerker. Der "Blick" haengt am Schwimmer (wohin man geworfen
  1669	// hat) plus einer traegen Eigendrift, damit die Szene auch in Ruhe atmet.
  1670	// Die Spielebene (Fische, Haken, Steg) bewegt sich NICHT - Tippkoordinaten
  1671	// bleiben Weltkoordinaten. Laeuft in beiden Renderern (Canvas-Transform).
  1672	const CAM_MAX = 30;                                   // px, Obergrenze der Drift
  1673	const PARA_SKY = 0.75, PARA_FAR = 0.45, PARA_NEAR = 0.16;
  1674	let camX = 0;

  1676	function updateCamera(dt) {
  1677	  const busy = gameState === "waiting" || gameState === "biting" || gameState === "reeling" || gameState === "bossfight";
  1678	  const look = busy ? bobberX : canvas.width / 2;
  1679	  const target = clamp((look - canvas.width / 2) / (canvas.width / 2), -1, 1) * 22
  1680	               + Math.sin(time * 0.16) * 7;
  1681	  camX = lerp(camX, clamp(target, -CAM_MAX, CAM_MAX), Math.min(1, dt * 1.6));
  1682	}

  1684	// Zeichnet eine Kulissen-Ebene seitlich versetzt und minimal vergroessert
  1685	// (die Vergroesserung deckt die Raender, die der Versatz freilegen wuerde).
  1686	// Anker ist die Wasserlinie, damit die Kulisse auf ihr stehen bleibt.
  1687	function withParallax(k, fn) {
  1688	  if (!k) { fn(); return; }
  1689	  ctx.save();
  1690	  const s = 1 + (2 * CAM_MAX * Math.abs(k)) / canvas.width;
  1691	  // ============ Der Versatz rastet auf ganze Geraetepixel ein (#107, R7) ====
  1692	  //
  1693	  // Zwei Gruende, und der zweite ist der wichtigere:
  1694	  //
  1695	  // 1. GEBACKENE KULISSEN. Ein Motiv vom Blech (blech.js) wird auf einen
  1696	  //    GANZEN Geraetepixel kopiert; die Unterpixel-Lage backt es mit. Wandert
  1697	  //    der Versatz stufenlos, wandert die Lage mit, und die Signatur waere
  1698	  //    jedes Bild eine andere — der Cache wuerde sich totbacken.
  1699	  // 2. SCHAERFE. Eine Kulisse, die auf halben Pixeln steht, wird beim
  1700	  //    Zeichnen weichgerechnet. Auf ganzen Pixeln steht sie scharf. Das gilt
  1701	  //    fuer den gebackenen UND fuer den direkten Weg — das Einrasten macht
  1702	  //    das Bild also nicht schlechter, sondern besser.
  1703	  //
  1704	  // Die Stufe ist ein Geraetepixel, bei 3x also ein Drittel CSS-Pixel. Die
  1705	  // Drift laeuft ueber Sekunden ueber 60 CSS-Pixel; dass sie das in Schritten
  1706	  // von 1/3 Pixel tut, ist nicht zu sehen.
  1707	  const d = ctx.getTransform().a || 1;
  1708	  const versatz = Math.round(camX * k * d) / d;
  1709	  ctx.translate(canvas.width / 2 + versatz, horizonY);
  1710	  ctx.scale(s, s);
  1711	  ctx.translate(-canvas.width / 2, -horizonY);
  1712	  fn();
  1713	  ctx.restore();
  1714	}
